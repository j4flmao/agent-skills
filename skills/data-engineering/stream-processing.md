# Stream Processing (Apache Flink)

## 1. Skill Context
**Focus**: Stateful, real-time event stream processing. Moving from batch (ETL runs at midnight) to continuous streams.
**Triggers**: apache-flink, stream-processing, stateful-streaming, watermarks.

## 2. Event Time vs. Processing Time
- **Processing Time**: The time the server received the event.
- **Event Time**: The actual timestamp generated by the mobile app (even if the phone was offline for 3 days).
Flink excels at handling out-of-order Event Time streams using **Watermarks** (a signal saying "I guarantee no more events older than 12:05 will arrive").

## 3. Stateful Checkpointing (Chandy-Lamport)
If a node crashes while calculating the "Top 10 users of the hour", how does it not lose count?
Flink uses the Chandy-Lamport algorithm to take distributed snapshots of the engine's internal RAM (State) and save it to S3 periodically, guaranteeing Exactly-Once processing semantics.
