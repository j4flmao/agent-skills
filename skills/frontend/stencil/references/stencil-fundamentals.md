# Stencil Fundamentals: Compiler Model, Reactivity, and Testing Basics

Stencil is a compiler (maintained by the Ionic team) that turns TypeScript + JSX components into standards-based Web Components (custom elements). This reference covers the mental model: what the compiler generates, encapsulation choices, reactivity rules, rendering, and the built-in test tools. Decorator details are in `stencil-components.md`; project setup in `stencil-setup.md`; output targets in `stencil-deployment.md`.

## What Stencil Produces

- Native custom elements usable in plain HTML and any framework.
- A small runtime with a virtual DOM, async rendering, and (with the `dist` output) lazy loading: the browser downloads a component's code only when the tag first appears.
- Type definitions (`components.d.ts`) and optional framework wrappers (React, Angular, Vue) generated by output targets.

Choose Stencil for design systems that must work across frameworks; for an app built entirely in one framework, native components of that framework are usually simpler.

## A Minimal Component

```tsx
import { Component, Prop, State, Event, EventEmitter, h, Host } from '@stencil/core';

@Component({
  tag: 'acme-counter',
  styleUrl: 'acme-counter.css',
  shadow: true,
})
export class AcmeCounter {
  /** Initial value, set from an attribute or property */
  @Prop() start = 0;

  @State() count: number;

  @Event() countChanged: EventEmitter<number>;

  componentWillLoad() {
    this.count = this.start;
  }

  private increment = () => {
    this.count += 1;
    this.countChanged.emit(this.count);
  };

  render() {
    return (
      <Host>
        <button type="button" onClick={this.increment} aria-label="Increment">
          <slot name="label">Count</slot>: {this.count}
        </button>
      </Host>
    );
  }
}
```

```html
<acme-counter start="5"><span slot="label">Clicks</span></acme-counter>
<script>
  document.querySelector('acme-counter')
    .addEventListener('countChanged', (e) => console.log(e.detail));
</script>
```

Tag names must contain a hyphen; use a consistent prefix (`acme-`) to avoid collisions.

## Encapsulation Options

| Option | Behaviour | Use |
|--------|-----------|-----|
| `shadow: true` | Shadow DOM: style and DOM encapsulation, native `<slot>` | Default for design systems |
| `scoped: true` | Light DOM with compiler-scoped CSS classes; slots emulated | When global styles or third-party scripts must reach inside |
| Neither | Plain light DOM, global CSS | Rare; app-specific components |

Shadow DOM implications: global CSS does not apply inside; style hooks must be exposed via CSS custom properties and `::part()`; form participation requires form-associated custom elements (see `stencil-advanced.md`).

## Reactivity Rules

| Decorator | Triggers re-render | Owned by |
|-----------|-------------------|----------|
| `@Prop()` | Yes, when set from outside | Parent/consumer |
| `@State()` | Yes, when reassigned internally | Component |
| Plain class field | No | Component (non-render data) |

- Change detection is by reference: mutate arrays/objects immutably.

```tsx
@State() items: string[] = [];

addItem(item: string) {
  this.items = [...this.items, item];   // re-renders
  // this.items.push(item);            // does NOT re-render
}
```

- Props are immutable from inside the component by default; use `@Prop({ mutable: true })` only when the component must update its own prop, and prefer emitting an event instead.
- `@Prop({ reflect: true })` mirrors the value to an attribute (useful for CSS attribute selectors).
- Attributes are strings: complex values (objects, arrays) must be set as properties via JavaScript, not attributes.
- `@Watch('propName')` runs when a prop/state changes (not on initial load); validate inputs there.

## Lifecycle Overview

```
connectedCallback → componentWillLoad → render → componentDidLoad
(on change) componentShouldUpdate → componentWillUpdate → render → componentDidUpdate
disconnectedCallback
```

- `componentWillLoad` can return a Promise to delay the first render (e.g. fetching data); keep it fast.
- Do not change state in `componentDidLoad`/`componentDidUpdate` unconditionally; it causes extra renders (Stencil warns about this).
- Clean up listeners, timers, and observers in `disconnectedCallback`; elements can be removed and re-attached.

## Events and Methods

- `@Event()` emits `CustomEvent`s that bubble and are composed by default, so they cross shadow boundaries.
- Name events in camelCase with a component-specific prefix (`acmeChange`) to avoid clashing with native events like `change`.
- `@Method()` exposes public async methods (`async open(): Promise<void>`); use sparingly — props and events are the primary API.

## Styling Basics

```css
:host { display: inline-block; --acme-counter-bg: var(--acme-color-surface, #fff); }
button { background: var(--acme-counter-bg); }
:host([disabled]) button { opacity: 0.5; }
```

- Always set a `display` on `:host`; custom elements default to `inline`.
- Expose theming through documented CSS custom properties; expose structural styling with `part="button"` for `::part(button)`.

## Testing Basics

Stencil ships a test runner built on Jest (spec tests) and Puppeteer (end-to-end tests):

```tsx
// acme-counter.spec.tsx
import { newSpecPage } from '@stencil/core/testing';
import { AcmeCounter } from './acme-counter';

it('renders the start value', async () => {
  // Arrange & Act
  const page = await newSpecPage({ components: [AcmeCounter], html: `<acme-counter start="3"></acme-counter>` });

  // Assert
  expect(page.root.shadowRoot.querySelector('button').textContent).toContain('3');
});
```

```tsx
// acme-counter.e2e.ts
import { newE2EPage } from '@stencil/core/testing';

it('emits countChanged on click', async () => {
  const page = await newE2EPage({ html: `<acme-counter></acme-counter>` });
  const spy = await page.spyOnEvent('countChanged');
  await page.click('acme-counter >>> button');
  expect(spy).toHaveReceivedEventDetail(1);
});
```

```bash
npx stencil test --spec          # unit/spec tests
npx stencil test --spec --e2e    # include browser tests
```

Stencil also documents integrations with other runners (e.g. WebdriverIO); check the current docs for the recommended setup in your Stencil version.

## Pitfalls

- Mutating arrays/objects in `@State` and wondering why the view does not update.
- Passing objects through attributes in HTML.
- Event names colliding with native DOM events.
- Global CSS expected to style shadow DOM internals.
- Heavy work in `componentWillLoad` blocking first paint.

## Checklist

- [ ] Prefixed, hyphenated tag names
- [ ] Encapsulation chosen deliberately (shadow by default)
- [ ] Immutable state updates; props not mutated internally
- [ ] Events namespaced; methods minimal
- [ ] `:host` display and documented CSS custom properties/parts
- [ ] Spec tests for rendering logic, e2e tests for interaction
