# Bare-Metal Rust

## Purpose
Rust removes whole classes of firmware bugs (buffer overruns, use-after-free, data races between ISR and main) at compile time while compiling to code comparable with C. This skill shows how to structure a `no_std` project, share state with interrupts soundly, pick between RTIC, Embassy and a plain superloop, and build/flash/debug with the standard toolchain.

## 1. The `no_std` Environment
- `#![no_std]` links only `core` (and optionally `alloc` if you provide a `#[global_allocator]`). No threads, files, or heap by default.
- `#![no_main]` + `cortex-m-rt`'s `#[entry]` provide the reset handler, vector table and `memory.x` linker layout.
- You must supply a panic handler: `panic-halt`, `panic-probe` (with defmt), or your own `#[panic_handler]`.

```rust
#![no_std]
#![no_main]

use cortex_m_rt::entry;
use panic_halt as _;

#[entry]
fn main() -> ! {
    let dp = pac::Peripherals::take().unwrap();   // singleton: second take() returns None
    // configure clocks/GPIO via the HAL ...
    loop {
        cortex_m::asm::wfi();                     // sleep until an interrupt
    }
}
```
`main` returns `!` — firmware never returns.

## 2. Crate Layers
| Layer | What it is | Example |
|-------|-----------|---------|
| PAC (Peripheral Access Crate) | Generated by `svd2rust` from the vendor SVD; register-level, mostly `unsafe` writes of raw bits are wrapped in typed field APIs | `stm32f4`, `nrf52840-pac` |
| HAL | Safe drivers implementing `embedded-hal` traits | `stm32f4xx-hal`, `nrf52840-hal`, `esp-hal` |
| `embedded-hal` 1.0 | Portable traits (`digital::OutputPin`, `spi::SpiDevice`, `i2c::I2c`, `delay::DelayNs`); `embedded-hal-async` for async | stable since Jan 2024 |
| BSP | Board pin mapping on top of the HAL | `microbit-v2` |
| Drivers | Device drivers generic over the traits | sensor crates |

Write drivers against `embedded-hal` traits so they run on any HAL.

## 3. Sharing State with Interrupts
`static mut` requires `unsafe` for every access, and in the 2024 edition creating references to it is denied by default (`static_mut_refs`). Use one of:

1. **critical-section Mutex** — portable, short critical sections:
```rust
use core::cell::RefCell;
use critical_section::Mutex;

static COUNTER: Mutex<RefCell<u32>> = Mutex::new(RefCell::new(0));

#[interrupt]
fn TIM2() {
    critical_section::with(|cs| *COUNTER.borrow_ref_mut(cs) += 1);
}

fn read_counter() -> u32 {
    critical_section::with(|cs| *COUNTER.borrow_ref(cs))
}
```
The `CriticalSection` token proves interrupts are masked (single core) while borrowing. Provide an implementation via `cortex-m`'s `critical-section-single-core` feature or your HAL.

2. **Atomics** (`core::sync::atomic`) for single words — no masking. Cortex-M0/M0+ lacks CAS (`fetch_add` etc.); use `portable-atomic` there.
3. **RTIC resources** — compile-time priority-ceiling locking (below).
4. **Embassy channels/signals** (`embassy-sync`) between async tasks and interrupts.

## 4. Concurrency Frameworks
| Option | Model | Choose when |
|--------|-------|-------------|
| Superloop + interrupts | `loop { wfi }` + ISRs | very small programs |
| RTIC 2 | Hardware tasks bound to interrupts, software tasks, Stack Resource Policy (priority ceiling) — deadlock-free, no runtime scheduler | hard real-time with static priorities; analysable timing |
| Embassy | `async`/`await` executor, async HALs (`embassy-stm32`, `embassy-nrf`, `embassy-rp`), timers, networking (`embassy-net`), USB, BLE via `nrf-softdevice`/`trouble` | I/O-heavy firmware, many concurrent waits, low power |
| RTOS bindings | FreeRTOS/Zephyr with Rust | mixing with existing C RTOS code |

## 5. Memory Without a Heap
- `heapless::{Vec, String, spsc::Queue, pool}` — fixed capacity in the type (`heapless::Vec<u8, 64>`).
- `static_cell::StaticCell` to obtain `&'static mut` buffers once at startup (common with Embassy).
- If `alloc` is truly needed, use `embedded-alloc` with a static arena and handle allocation failure.
- Check stack usage: `flip-link` puts the stack below `.data/.bss` so overflow faults instead of silently corrupting statics.

## 6. Toolchain
```toml
# .cargo/config.toml
[build]
target = "thumbv7em-none-eabihf"      # Cortex-M4F/M7

[target.thumbv7em-none-eabihf]
runner = "probe-rs run --chip STM32F411CEUx"
rustflags = ["-C", "link-arg=-Tlink.x", "-C", "link-arg=-Tdefmt.x"]
```
- `rustup target add thumbv7em-none-eabihf`; `cargo run --release` flashes and streams logs.
- `probe-rs` (flash, RTT, GDB server) replaced most OpenOCD workflows; `defmt` + `defmt-rtt` give compact deferred-formatted logging.
- Size: `cargo size --release` (cargo-binutils); set `opt-level = "s"` or `"z"`, `lto = true`, `codegen-units = 1`, `panic = "abort"` in the release profile.

## 7. Anti-Patterns
| Anti-pattern | Problem | Fix |
|--------------|---------|-----|
| `static mut` + `unsafe` everywhere | data races the compiler cannot see | `Mutex<RefCell<_>>`, atomics, RTIC/Embassy |
| Long work inside `critical_section::with` | adds to interrupt latency | copy out, process outside |
| `unwrap()` on fallible HAL calls in production | panic = reset/halt | handle errors, log with defmt |
| Blocking delays in Embassy tasks | stalls the whole executor | `Timer::after(...).await` |
| Writing PAC registers alongside a HAL that owns the peripheral | breaks HAL invariants | let one owner configure each peripheral |

## 8. Checklist
- [ ] `#![no_std]`, `#![no_main]`, panic handler chosen deliberately
- [ ] Peripherals taken once; ownership moved into drivers/tasks
- [ ] Every ISR-shared value behind a sound primitive (no `static mut`)
- [ ] No heap, or a bounded allocator with failure handling
- [ ] Release profile optimised; size and stack measured; `flip-link` enabled
- [ ] Logs via defmt; flashing/debugging via probe-rs
