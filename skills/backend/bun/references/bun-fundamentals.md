# Bun Fundamentals: Runtime Model, Modules, Configuration and Node.js Compatibility

Bun is a JavaScript/TypeScript runtime built on JavaScriptCore (Safari's engine) and written in Zig, bundling a package manager, test runner and bundler in one binary. This reference covers the runtime model, project setup, module resolution, TypeScript handling, environment variables, `bunfig.toml`, scripts and Node.js compatibility. HTTP, file and SQLite APIs are in `bun-essentials.md`; package manager and tests in `bun-tooling.md`.

## What Bun Replaces

| Node.js toolchain | Bun equivalent |
|-------------------|----------------|
| `node` | `bun run` / `bun file.ts` |
| `npm` / `pnpm` / `yarn` | `bun install`, `bun add`, `bun remove` |
| `npx` | `bunx` |
| `ts-node` / `tsx` | Native TypeScript and JSX execution |
| Jest / Vitest | `bun test` (Jest-compatible API) |
| esbuild / webpack (basic cases) | `bun build` |
| `dotenv` | Automatic `.env` loading |
| `nodemon` | `bun --watch`, `bun --hot` |

You can adopt pieces independently: many teams use `bun install` and `bun test` while still deploying on Node.js.

## Installing and Starting a Project

```bash
curl -fsSL https://bun.sh/install | bash      # macOS/Linux; Windows: powershell -c "irm bun.sh/install.ps1 | iex"
bun --version
bun upgrade                                    # update the runtime

bun init                                       # package.json, tsconfig.json, index.ts, .gitignore
bun add zod
bun add -d @types/bun
bun run index.ts
```

Pin the Bun version for teams and CI (`packageManager` field, `.bun-version` used by setup actions, or the Docker image tag) so everyone runs the same runtime.

## Executing Code

```bash
bun index.ts               # run a file (TS, TSX, JS, JSX)
bun run dev                # run a package.json script
bun --watch index.ts       # restart the process on file changes
bun --hot server.ts        # hot reload modules in place, keeping the process (and server) alive
bun --env-file=.env.staging index.ts
```

`bun run <script>` starts noticeably faster than `npm run`. Scripts run with `bun` available on PATH; to make scripts that call `node` use Bun instead, run `bun --bun run <script>`.

## TypeScript and JSX

- Bun transpiles TypeScript on the fly; it **does not type-check**. Run `tsc --noEmit` (or your editor) in CI for type errors.
- `@types/bun` provides types for the `Bun` global and `bun:*` modules.
- Recommended `tsconfig.json` settings for Bun projects: `"module": "Preserve"`, `"moduleResolution": "bundler"`, `"target": "ESNext"`, `"verbatimModuleSyntax": true`, `"noEmit": true`, `"types": ["bun"]` (generated by `bun init`).
- JSX works without configuration; the `jsx` and `jsxImportSource` options from `tsconfig.json` are respected.

## Modules

- ES modules and CommonJS both work, including mixing `import` and `require` in the same project.
- Top-level `await` is supported.
- `tsconfig.json` `paths` aliases are honored at runtime.
- Import attributes for non-JS assets: `import data from "./data.json"`, `import config from "./config.toml"`, `import text from "./query.sql" with { type: "text" }`.
- `import.meta.dir`, `import.meta.file`, `import.meta.path` give the current module's location; `import.meta.main` is true when the file is the entry point.

```ts
if (import.meta.main) {
  await main();
}
```

## Environment Variables

Bun loads these files automatically (later files override earlier ones):

| File | Loaded when |
|------|-------------|
| `.env` | Always |
| `.env.production` / `.env.development` / `.env.test` | `NODE_ENV` matches (`bun test` sets `test`) |
| `.env.local` | Always, except when `NODE_ENV=test` |

```ts
const port = Number(Bun.env.PORT ?? 3000);     // same object as process.env
const dbUrl = Bun.env.DATABASE_URL;
if (!dbUrl) throw new Error("DATABASE_URL is not set");
```

Type environment variables by augmenting the interface:

```ts
declare module "bun" {
  interface Env {
    DATABASE_URL: string;
    PORT?: string;
  }
}
```

Do not commit `.env` files with secrets; inject secrets from the platform in production. Disable automatic loading with `--no-env-file` when the platform provides the environment.

## bunfig.toml

Optional project configuration for runtime, installer and test runner:

```toml
# bunfig.toml
preload = ["./instrumentation.ts"]   # modules loaded before the entry point

[install]
exact = true                          # save exact versions on bun add
# registry = "https://registry.npmjs.org"

[install.scopes]
"@acme" = { url = "https://npm.acme.example/", token = "$ACME_NPM_TOKEN" }

[test]
preload = ["./test/setup.ts"]
coverage = true
coverageThreshold = 0.8
```

Reference tokens through environment variables as shown; never hardcode registry credentials.

## Node.js Compatibility

Bun implements most Node.js APIs (`node:fs`, `node:path`, `node:http`, `node:crypto`, `node:stream`, `node:child_process`, `node:worker_threads`, and others) and loads npm packages from `node_modules`. Most frameworks (Express, Hono, Fastify, Elysia, Prisma, Drizzle) run on Bun.

Points to check before migrating:
- Compatibility is tracked per module on Bun's Node.js compatibility page; a few APIs are partial or missing.
- Native addons using N-API generally work; packages depending on V8-specific internals may not.
- Behavior differences can appear in edge cases (stream timing, error messages); run your full test suite under Bun.
- Tooling that shells out to `node` keeps using Node unless invoked with `--bun`.

## Web Standard APIs

Bun exposes web-standard globals: `fetch`, `Request`, `Response`, `Headers`, `URL`, `WebSocket`, `ReadableStream`, `TextEncoder`, `crypto.subtle`, `crypto.randomUUID()`, `structuredClone`, `AbortController`, `FormData`, `Blob`. Code written against these APIs is portable to Deno, Cloudflare Workers and modern Node.js.

```ts
const res = await fetch("https://api.example.com/items", {
  signal: AbortSignal.timeout(5_000),           // always bound network calls
});
if (!res.ok) throw new Error(`Upstream returned ${res.status}`);
const items = await res.json();
```

## Project Structure Example

```text
my-service/
  bunfig.toml
  package.json
  bun.lock                 # text lockfile (default since Bun 1.2); commit it
  tsconfig.json
  src/
    index.ts               # entry: starts server
    routes/
    db/
  test/
    setup.ts
    users.test.ts
```

```json
{
  "name": "my-service",
  "type": "module",
  "scripts": {
    "dev": "bun --hot src/index.ts",
    "start": "bun src/index.ts",
    "test": "bun test",
    "typecheck": "tsc --noEmit",
    "build": "bun build src/index.ts --target=bun --outdir=dist"
  }
}
```

## Common Mistakes

| Mistake | Fix |
|---------|-----|
| Assuming `bun` type-checks | Add `tsc --noEmit` to CI |
| Unpinned Bun version across machines | Pin in CI and Docker images |
| Secrets in `.env` committed to Git | Platform-injected secrets; `.env` in `.gitignore` |
| Using `--hot` in production | Use plain `bun` with a process manager or container restarts |
| Not testing Node-specific dependencies under Bun | Run the full test suite before switching runtimes |

## Checklist

- [ ] Bun version pinned locally, in CI and in images
- [ ] `@types/bun` installed; `tsc --noEmit` in CI
- [ ] `bun.lock` committed
- [ ] `.env` handling understood; secrets injected by the platform
- [ ] Node.js compatibility of critical dependencies verified by tests
- [ ] Network calls bounded with `AbortSignal.timeout`
