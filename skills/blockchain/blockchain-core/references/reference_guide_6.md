# Testing and Simulating Blockchain Protocols

Test strategy for protocol and node code (consensus, networking, state transition), as opposed to smart-contract testing. Covers the test pyramid for clients, shared conformance suites, deterministic simulation, fuzzing, devnets and testnets.

## Test Pyramid for Clients

```text
            ┌──────────────────────┐
            │ public testnets       │  real network conditions, fork rehearsals
            ├──────────────────────┤
            │ multi-client devnets  │  Kurtosis / Hive / local regtest clusters
            ├──────────────────────┤
            │ deterministic sims    │  many nodes, simulated network & clock
            ├──────────────────────┤
            │ conformance vectors   │  shared spec tests, cross-client
            ├──────────────────────┤
            │ unit + property + fuzz│  pure functions, encoders, state transition
            └──────────────────────┘
```

## Unit and Property Tests

Target pure components: serialization, hashing, signature verification, difficulty/base-fee formulas, fork-choice scoring.

```python
from hypothesis import given, strategies as st

def next_base_fee(parent_base: int, gas_used: int, gas_target: int) -> int:
    if gas_used == gas_target:
        return parent_base
    delta = parent_base * abs(gas_used - gas_target) // gas_target // 8
    if gas_used > gas_target:
        return parent_base + max(delta, 1)
    return parent_base - delta

@given(st.integers(1, 10**12), st.integers(0, 60_000_000), st.integers(1, 30_000_000))
def test_base_fee_moves_at_most_one_eighth(base, used, target):
    used = min(used, 2 * target)
    nxt = next_base_fee(base, used, target)
    assert abs(nxt - base) <= base // 8 + 1
    assert nxt >= 0
```

Properties worth asserting:
- Encode/decode round-trips (RLP, SSZ, Bitcoin serialization).
- Fork choice is deterministic given the same message set regardless of arrival order (where the spec says it should be).
- State transition never creates or destroys value except via defined issuance/burn.
- Merkle proofs generated by the tree verify; mutated proofs fail.

## Conformance Test Suites

| Ecosystem | Suite | What it checks |
|-----------|-------|----------------|
| Ethereum consensus | `ethereum/consensus-spec-tests` (generated from the Python executable spec) | State transition, fork choice, SSZ, BLS per fork |
| Ethereum execution | `ethereum/execution-spec-tests` (EEST) and legacy `ethereum/tests` | Block/state tests, opcode and precompile behaviour per fork |
| Ethereum cross-client | Hive | Runs real clients in containers against scenario simulators (sync, Engine API, RPC) |
| Bitcoin | Bitcoin Core `test/functional` (Python, regtest) and unit tests; script test vectors in `src/test/data` | RPC behaviour, P2P, consensus scripts |

Running shared vectors is the main defence against consensus splits between implementations: two clients that disagree on one vector will fork on mainnet if that case occurs.

## Deterministic Simulation

Run many nodes in one process with a simulated clock, network and randomness seeded by the test, so any failure replays exactly.

Design rules:
- All time via an injected clock; no wall-clock reads.
- All network via an in-memory transport that can delay, drop, duplicate, reorder and partition messages.
- All randomness from a seeded PRNG passed in.
- Assert safety (no two finalized conflicting blocks) and liveness (finality progresses once the network heals) as invariants checked every step.

```python
def run_sim(seed: int, nodes: int, steps: int) -> None:
    rng = random.Random(seed)
    net = SimNetwork(rng, drop=0.05, max_delay_ms=800)
    cluster = [Node(i, net, clock=net.clock) for i in range(nodes)]
    for step in range(steps):
        if step == 200:
            net.partition({0, 1}, set(range(2, nodes)))
        if step == 400:
            net.heal()
        net.tick()
        finalized = {n.finalized_at(h) for n in cluster for h in n.finalized_heights()}
        assert no_conflicts(finalized), f"safety violated seed={seed} step={step}"
```

Run thousands of seeds in CI and keep the failing seed in the bug report.

## Fuzzing

| Target | Technique |
|--------|-----------|
| Deserializers (blocks, txs, P2P messages) | Coverage-guided (libFuzzer, cargo-fuzz, Go native fuzzing) |
| EVM / script interpreter | Differential fuzzing across implementations (compare post-state) |
| P2P state machines | Stateful fuzzing of message sequences |

```go
func FuzzDecodeTx(f *testing.F) {
    f.Add([]byte{0x02, 0xc0})
    f.Fuzz(func(t *testing.T, data []byte) {
        tx, err := DecodeTx(data)
        if err != nil {
            return
        }
        out, err := EncodeTx(tx)
        if err != nil {
            t.Fatalf("re-encode failed for %x: %v", data, err)
        }
        if !bytes.Equal(out, data) {
            t.Fatalf("non-canonical round trip: in=%x out=%x", data, out)
        }
    })
}
```

Bitcoin Core maintains libFuzzer targets in `src/test/fuzz`; differential EVM fuzzers (e.g. goevmlab) compare clients' traces.

## Devnets

### Bitcoin regtest
```bash
bitcoind -regtest -daemon -fallbackfee=0.0002
bitcoin-cli -regtest createwallet test
ADDR=$(bitcoin-cli -regtest getnewaddress)
bitcoin-cli -regtest generatetoaddress 101 "$ADDR"   # 100-block coinbase maturity + 1
bitcoin-cli -regtest getbalance
```

### Ethereum multi-client devnet with Kurtosis
```yaml
# network_params.yaml for ethpandaops/ethereum-package
participants:
  - el_type: geth
    cl_type: lighthouse
    count: 2
  - el_type: nethermind
    cl_type: teku
network_params:
  seconds_per_slot: 6
```
```bash
kurtosis run github.com/ethpandaops/ethereum-package --args-file network_params.yaml
```

Use devnets to rehearse forks: set the fork epoch/timestamp a few minutes ahead and watch every client cross it.
