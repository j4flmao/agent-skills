# Bitcoin Core Node Operations

Running Bitcoin Core for exchanges, wallets, explorers, and payment backends: configuration, indexes, RPC security, ZMQ notifications, Electrum-protocol servers, and upgrade practice.

## Node Roles

| Role | Key settings |
|------|-------------|
| Backend for a wallet/payment service | `txindex` usually unnecessary if the service tracks its own addresses; ZMQ for new blocks/txs |
| Explorer / indexer | `txindex=1`, Electrum server or custom indexer, generous `dbcache` |
| Lightweight infra node | `prune=<MiB>` to cap disk, no `txindex` |
| Lightning backend | Unpruned or carefully pruned node with ZMQ; check the Lightning implementation's requirements |

## bitcoin.conf

```ini
# Network
server=1
listen=1
maxconnections=125

# Performance
dbcache=4096          # MiB; increase during initial block download, reduce afterwards if RAM is tight

# Indexes
txindex=1             # full transaction index (incompatible with prune)
blockfilterindex=1    # BIP158 compact block filters (for light clients / rescans)

# Wallet
disablewallet=1       # infra nodes should not hold keys

# RPC
rpcbind=127.0.0.1
rpcallowip=127.0.0.1
rpcauth=appuser:<salt>$<hash>   # generated by share/rpcauth/rpcauth.py
rpcthreads=8
rpcworkqueue=64

# Notifications
zmqpubrawblock=tcp://127.0.0.1:28332
zmqpubrawtx=tcp://127.0.0.1:28333
zmqpubhashblock=tcp://127.0.0.1:28334
```

Network-specific sections (`[main]`, `[test]`, `[testnet4]`, `[signet]`, `[regtest]`) apply settings per chain; `rpcbind`, ports, and some options must be placed in the right section when running non-mainnet chains.

## Ports

| Port | Purpose | Exposure |
|------|---------|----------|
| 8333 | Mainnet P2P | Public (inbound helps the network; optional) |
| 8332 | Mainnet RPC | Localhost/private only |
| 48333 / 18333 / 38333 | Testnet4 / testnet3 / signet P2P | As needed |
| 2833x | ZMQ (configurable) | Localhost/private only |

## RPC Authentication

- Use `rpcauth` (salted hash in config) instead of `rpcuser`/`rpcpassword` in plain text. The script ships in the source tree: `share/rpcauth/rpcauth.py appuser`.
- Cookie authentication (`.cookie` file in the datadir) works for local tools running as the same user.
- RPC is not designed for public exposure: no TLS, coarse permissions. Use `rpcwhitelist` to restrict which methods each user can call, and expose only via an authenticated proxy if remote access is required.

```ini
rpcwhitelist=appuser:getblockchaininfo,getblock,getrawtransaction,sendrawtransaction,estimatesmartfee
rpcwhitelistdefault=0
```

## Initial Block Download (IBD)

- Raise `dbcache` substantially during IBD (several GiB if RAM allows) to reduce disk writes; lower it after sync.
- `assumevalid` (enabled by default) skips signature checks for blocks before a hard-coded, reviewed block hash; it does not skip other validation.
- AssumeUTXO (`loadtxoutset` RPC) lets a node start from a UTXO snapshot and validate history in the background; available on mainnet in recent releases. Snapshot hashes are hard-coded in the release, so only matching snapshot files are accepted.
- Use fast local SSD; HDD-based IBD is very slow due to chainstate random I/O.

## Useful Commands

```bash
bitcoin-cli getblockchaininfo        # blocks, headers, verificationprogress, pruned
bitcoin-cli getnetworkinfo           # version, connections, local addresses
bitcoin-cli getpeerinfo | jq length
bitcoin-cli getmempoolinfo
bitcoin-cli getindexinfo             # txindex / blockfilterindex sync status
bitcoin-cli estimatesmartfee 6
bitcoin-cli -rpcwait stop            # clean shutdown
```

## ZMQ Notifications

ZMQ publishes raw blocks and transactions as they arrive. Consumers must handle:

- Missed messages (ZMQ is fire-and-forget): on reconnect, reconcile using `getblockcount` / `getbestblockhash`.
- Reorgs: track block hashes and heights; when a new block's parent is not your tip, walk back and re-process.
- Transactions that leave the mempool without confirmation (replacement, eviction).

## Confirmations and Reorgs

- Credit deposits only after an agreed number of confirmations based on value and risk (commonly several confirmations for significant amounts).
- Treat 0-conf as untrusted; RBF (replace-by-fee) is widely used and full-RBF is the default mempool policy in recent Bitcoin Core versions.
- Store block hash with every credited transaction to detect reorgs.

## Electrum-Protocol Servers

| Server | Notes |
|--------|-------|
| electrs | Rust, efficient, popular for personal and small deployments |
| Fulcrum | C++, fast, suited to heavy public use |
| ElectrumX | Python, long-standing |

They require an unpruned node (typically with `txindex` or their own index) and add a few hundred GB of index data. Do not expose without TLS and rate limits.

## Privacy and Network Options

```ini
proxy=127.0.0.1:9050     # route outbound via Tor
listenonion=1
onlynet=onion            # optional: Tor-only
```

Useful for privacy-sensitive deployments; mixed clearnet + Tor improves eclipse resistance.

## Upgrades

- Read release notes for changed defaults (mempool policy, deprecated RPCs, config option renames).
- Stop cleanly with `bitcoin-cli stop`; never `kill -9` (forces chainstate recovery or reindex).
- Some upgrades rebuild indexes on first start; plan downtime.
- Verify release binaries with `SHA256SUMS` and the signed `SHA256SUMS.asc` (builder keys), or build reproducibly (Guix).

```bash
sha256sum --ignore-missing --check SHA256SUMS
gpg --verify SHA256SUMS.asc SHA256SUMS
```

## Backup and Recovery

- Infra nodes without wallets can be resynced, but snapshots (filesystem or volume) of a cleanly stopped datadir restore faster.
- `-reindex` rebuilds block index and chainstate from local block files; `-reindex-chainstate` only rebuilds chainstate.
- Any wallets (if used) need separate encrypted backups; descriptor wallets: back up descriptors and keys.

## Monitoring

| Signal | Source |
|--------|--------|
| `blocks` vs `headers`, tip age | `getblockchaininfo` |
| Peer count, inbound/outbound | `getnetworkinfo`, `getpeerinfo` |
| Mempool size and min fee | `getmempoolinfo` |
| Index sync status | `getindexinfo` |
| Disk, RAM, I/O wait | Node exporter |

Alert when tip age exceeds ~1 hour (blocks are ~10 minutes on average but variance is high), and when the node's tip differs from independent references.

## Pitfalls

- Exposing 8332 to the internet.
- Enabling `prune` and expecting `txindex` or Electrum servers to work.
- Using `rpcpassword` in plain text config committed to repos.
- Ignoring reorg handling in deposit processing.

## Checklist

- [ ] RPC bound locally, `rpcauth` + `rpcwhitelist`
- [ ] ZMQ consumers reconcile and handle reorgs
- [ ] Confirmation policy documented per value tier
- [ ] Verified binaries; clean shutdowns; upgrade notes reviewed
